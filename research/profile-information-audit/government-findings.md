## Key Facts

- **EPA all-years, non-2027 cohort — 3,605 profiles.** The official FuelEconomy.gov page labels the all-years dataset as model years 1984–2026; it identifies vehicle testing at EPA’s National Vehicle and Fuel Emissions Laboratory and manufacturer testing under EPA oversight. It links CSV/XML downloads and format documentation, and separately lists MY2027 material. The prior exact-row audit covered 3,639 profiles / 18,764 referenced vehicle rows, including 34 MY2027 profiles; all referenced IDs, make/year labels, model labels, and EPA base-model groups matched the live file on 2026-10-08. Thus 3,605 is the source-defined EPA cohort excluding MY2027, not a separately reported count of matched source rows. Exact members are the `catalog-profiles.csv` rows with `source_id=epa-1984-present` and `year != 2027`. The source records establish matching EPA fuel-economy identities, not all U.S. retail offerings or exact trims. [Download page](https://www.fueleconomy.gov/feg/download.shtml), exact scope MY1984–2026; [prior row audit](research/catalog-source-verification.md). Evidence: `research/sources/full-verification-government-01-page.md`.

- **EPA annual-guide cohort — 488 profiles, MY1978–1983.** EPA’s archive explicitly links separate ZIP data files for each of those six model years, describes the files as importable into databases or spreadsheets, and links instructions for MY1978–2001. The exact-row audit reports all six source-file checksums matched and all 908 recorded line locators matched their model labels. Counts by MY are 52 / 52 / 48 / 96 / 114 / 126. These records evidence labels in the EPA guide/test-data archive, not a complete U.S. sales list or exact configurations. Exact profile IDs are all rows with `source_id=epa-guide-1978` through `epa-guide-1983` in `catalog-profiles.csv`. [EPA annual-guide archive](https://www.epa.gov/compliance-and-fuel-economy-data/test-data-annual-fuel-economy-guide). Evidence: `research/sources/full-verification-government-02-page.md`; row-level audit: `research/catalog-source-verification.md`.

- **vPIC supplements — 6 profiles, matched via 5 year-scoped queries.** Exact IDs: `ram-2500-2024-model-year`, `ram-3500-2024-model-year`, and `tesla-roadster-2008-model-year` through `tesla-roadster-2011-model-year`. The prior query audit found both Ram model labels in one MY2024 make query and each Tesla Roadster label in its requested MY2008–2011 query. vPIC says its dataset is manufacturer-submitted information through Part 565, used to capture how manufacturers assign VINs and decode vehicle information. It does not describe a U.S. retail-sales census. The query match supports the returned make/model relation within the requested year scope; it does not prove retail sale, exhaustive availability, or exact configuration. [vPIC API documentation](https://vpic.nhtsa.dot.gov/api); [exact captures and query audit](research/catalog-source-verification.md) and `research/sources/catalog-vpic-01-identity-check.md` through `catalog-vpic-05-identity-check.md`. Evidence: `research/sources/full-verification-government-03-page.md`.

- **EPA source-use metadata.** EPA’s general data-licensing statement says EPA-produced data are public domain by default **unless otherwise specified**, and advises users to consult associated dataset metadata for limitations, restrictions, and intended use. FuelEconomy.gov’s download page provides data-format documentation and scope/provenance details, but the inspected page does not itself expose dataset-specific reuse terms, a version archive, or checksums. The annual-guide page likewise supplies year-specific files and instructions but no distinct reuse statement. This gives a favorable general basis for EPA-produced facts, not affirmative evidence that every field in the combined EPA/manufacturer-testing dataset has identical provenance or terms. It does **not** create a requirement to obtain manufacturer permission merely because a fact concerns a manufacturer’s vehicle. [EPA license](https://edg.epa.gov/EPA_Data_License.htm), exact stated scope: EPA-produced data unless otherwise specified; `research/sources/release-review-epa-fuel-economy-01-epa-license.md`.

- **vPIC use conditions.** NHTSA’s FAQ says its API is free for public use without an application license or registration, asks users to schedule large batches considerately, and describes lower decode confidence for MY1980–1994 and no vPIC VIN-standard data before 1980. The current six supplements are make/model/year listings, not bulk VIN decodes. API docs also state automated traffic rate control. This supports public API access for the narrow query use reviewed; it is not a blanket statement about every downstream use or a completeness warranty. [FAQ](https://vpic.nhtsa.dot.gov/api/home/index/faq); `research/sources/release-review-nhtsa-vpic-02-vpic-faq.md`.

## Notable Claims Requiring Cross-Reference

- An EPA or vPIC listing proves the presence of a record with the returned source labels; it does **not** by itself prove that a vehicle was sold/delivered in the U.S., establish every retail model in a year, or prove that an absent name was unavailable. EPA test/guide coverage and manufacturer VIN submissions have defined program scopes.
- Structural matching is not independent factual verification of real-world retail availability. The previous audit establishes row/locator consistency against the cited sources. It does not reconstruct the national market.
- A make/model/year identity is not exact configuration evidence: it does not establish trim, body, engine, drivetrain, packages, or a compatible retail combination.
- Source-use permission is a separate gate from matching and factual truth. The EPA default public-domain statement applies to EPA-produced data unless otherwise specified and directs users to associated metadata. No examined dataset page supplied a complete field-by-field provenance/rights statement. This unresolved metadata question should be scoped to the actual dataset and intended use—not converted into a blanket manufacturer-permission demand for government-published facts.
- The checksum discrepancy cannot be explained from the page’s update date alone; preserve both hashes and the archive/live distinction rather than attributing the mismatch to a known file change.
