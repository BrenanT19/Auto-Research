1. COMPARE PAGE
-----------------------------------

Keep the current Compare page and its ability to compare up to 4 vehicles.

I noticed a UX issue with the vehicle search field.

After a user searches for a vehicle and selects it, completely clear the search input and close the suggestion dropdown.

Example:

User types:
"Tesla"

They select:
2024 Tesla Model Y Long Range

After selection:
- Add the vehicle to the comparison.
- Clear "Tesla" from the search field.
- Return the search field to its normal placeholder state.
- Close the dropdown.
- Allow the user to immediately search for another vehicle.

Repeat this behavior after every vehicle selection.

Once 4 vehicles have been selected:
- Keep the existing 4-vehicle maximum.
- The dropdown should remain closed.
- Clearly communicate that 4 of 4 vehicles are selected.
- Do not allow a fifth vehicle unless one of the existing vehicles is removed.

If a vehicle is removed, searching should become available again.

Preserve the current comparison table and its general visual design.

Do not make major changes to the comparison data yet because the automotive data system will be improved in a later stage.

2. CALCULATOR – FIX NUMBER INPUT BEHAVIOR
-----------------------------------

There is an annoying behavior in the ownership calculator's numeric fields.

Currently, if I delete the existing number until the field reaches 0 and then type a new number, the existing zero can remain in front.

Example:

I delete a maintenance value.

The field becomes:
0

Then I type:
500

It can display:
0500

Fix this behavior across ALL numeric calculator fields.

Desired behavior:

Users must be able to temporarily leave a numeric field completely blank while editing.

Do NOT automatically force "0" into the input while the user is typing.

For example:

110
→ user deletes it
→ field becomes blank
→ user types 500
→ field displays 500

NOT:
0500

The calculations should remain stable while a field is temporarily empty. Internally, an empty value can be treated safely for calculations, but the UI should not force a visible zero into the field while the user is editing.

On blur, if a value is required, it may safely normalize to an appropriate default.

Apply this behavior consistently to:
- Vehicle price
- Down payment
- APR
- Miles driven per year
- Fuel price
- Fuel economy
- Insurance
- Maintenance
- Repair reserve
- Any other editable numeric calculator fields

Do not change the overall calculator design.

Keep the live monthly/yearly ownership estimate panel.
